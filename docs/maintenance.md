# Maintenance

## What the baseline does on every run

`baseline.yml` starts with `apt_upgrade`, which refreshes the package index and
applies pending upgrades. Every later role therefore configures a patched
system, and a package the baseline installs is not immediately superseded by one
that was already pending.

`apt_maintenance` then configures periodic behaviour:

| Setting | Value | Meaning |
|---|---|---|
| `APT::Periodic::Update-Package-Lists` | `1` | Refresh the package index daily |
| `APT::Periodic::Download-Upgradeable-Packages` | `0` | Do not download upgrades |
| `APT::Periodic::Unattended-Upgrade` | `0` | Do not apply upgrades |
| `APT::Periodic::AutocleanInterval` | `7` | Clear the package cache weekly |

The periodic policy only refreshes the index; it never downloads or installs
anything. Upgrades are applied by `apt_upgrade` at the start of each
`baseline.yml` run, which is a deliberate, observable moment rather than an
unattended one.

`apt_upgrade` defaults to `baseline_apt_upgrade_mode: safe`, which runs
`apt-get upgrade` and never removes a package. Set it to `full` to run
`apt-get dist-upgrade`, which also applies upgrades that need new or removed
packages. `baseline_apt_upgrade_autoremove` and `baseline_apt_upgrade_autoclean`
both default to `false`.

## Reviewing what an upgrade would do

`make maintenance` writes `/var/log/server-baseline/maintenance-report.txt`:

| Section | Contents |
|---|---|
| Pending upgrades | Every package `apt-get -s dist-upgrade` would install |
| Critical updates | The subset matching `linux-image`, `openssh`, `sudo`, `systemd`, `libc6` or `nftables` |
| Security support | The output of `debian-security-support --check` |
| Pending service restarts | The output of `needrestart -b` |
| Reboot required | Whether `/var/run/reboot-required` exists |

Nothing is upgraded and nothing is rebooted. The report is a simulation.

The four review packages are installed by `apt_maintenance`:

- `apt-listchanges` shows the changelog entries an upgrade would bring.
- `apt-listbugs` shows release-critical bugs filed against the candidates.
- `debian-security-support` reports packages that no longer receive security
  support.
- `needrestart` reports which services are running code that has been replaced
  on disk.

## Applying upgrades

```bash
make maintenance                 # read the report first
make vagrant-ssh                 # or ssh to the host
sudo apt-get update
sudo apt-get upgrade             # or dist-upgrade
sudo needrestart                 # restart services whose binaries changed
```

## Kernel updates

`apt_upgrade` installs new kernel packages but never reboots. The running kernel
is therefore not necessarily the newest installed one.

`make maintenance` reports both: `## Pending upgrades` lists a new
`linux-image` package, and `## Reboot required` reflects
`/var/run/reboot-required`. `needrestart -b` reports `NEEDRESTART-KSTA`, where
`2` means a newer kernel is installed and `3` means the running kernel no longer
matches the installed one.

Reboot when the report says so:

```bash
sudo reboot
```

## Service restarts

`needrestart -b` lists the services whose binaries or libraries changed. Restart
them with `sudo needrestart` (interactive) or
`sudo systemctl restart <unit>`.

## Reports

`/var/log/server-baseline/` holds plain text reports, mode `0640 root:root`:

| File | Produced by |
|---|---|
| `service-audit.txt` | `baseline.yml` (role `service_audit`) |
| `kernel-status.txt` | `baseline.yml` (role `kernel_status`) |
| `storage.txt` | `baseline.yml` (role `storage_checks`) |
| `maintenance-report.txt` | `make maintenance` |
| `security-audit.txt` | `make security-audit` |

The first three are regenerated by every `baseline.yml` run. The last two are
produced on demand. `logrotate` rotates the directory weekly, keeping eight
generations.

## Verifying the baseline

```bash
make verify
```

`verify.yml` runs `preflight` and `verification` and changes nothing. It asserts
the operating system, hostname, timezone, locale, administrative user and its
key, the SSH daemon configuration, the firewall, persistent logging, log
rotation, the required packages, the APT configuration and the presence of the
baseline reports.
